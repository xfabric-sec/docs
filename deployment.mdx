Cielara runs as a set of containerized services deployed on Kubernetes using a Helm chart.

## Requirements

### Infrastructure

| Requirement | Minimum |
|---|---|
| Kubernetes version | 1.35+ |
| Nodes | 2 nodes, each with 4 vCPU and 16 GB RAM |
| Storage | 30 GB for PVCs |

### Backing services

Cielara requires a PostgreSQL server (with pgvector) and RabbitMQ. The Helm chart manages RabbitMQ. PostgreSQL requires a minimum of 1 vCPU and 4 GB RAM.

### License key

A Keygen license key is required to pull container images from the private registry and to validate your installation. Contact Cielara to obtain a license.

## Preparing your EKS cluster

```bash
mkdir cielara-prepare-eks && cd cielara-prepare-eks
# Download the generated main.tf from the Cielara deploy form into this folder.

aws sso login --profile <profile> && export AWS_PROFILE=<profile>

# Already prepared (script or lost state)? Use the deploy form's "already
# prepared" toggle — the downloaded file carries migrate = true and the import blocks.

terraform init
terraform plan     # migrating: only imports + the marker additions, 0 destroy
terraform apply
terraform plan     # must print: No changes.
# handback: cielara-creds.json -> Cielara deploy form (or `terraform output -raw role_arn`)
```

For full documentation, see the [Terraform module registry](https://registry.terraform.io/modules/causal-dynamics-lab/cielara-prepare-eks/aws/latest).

## After deployment

Once the services are running:

1. Open the frontend URL in your browser.
2. Log in with the `ADMIN_EMAIL` and `ADMIN_PASSWORD` you configured. You'll be prompted to change the password on first login.
3. Accept the terms of service.
4. Complete the [LLM provider setup wizard](/guides/admin-tasks#configuring-an-llm-provider).
5. Set up your first [connections](/connections) (GitHub, cloud providers, workplace tools).
