## Navigating the topology

Click **World Model** in the sidebar. The full-screen canvas shows your services as card-shaped nodes inside nested cluster and namespace containers.

### Basic navigation

Pan by clicking and dragging the background. Zoom with the scroll wheel or a pinch gesture; zoom controls in the bottom-left corner offer in, out, and fit-view buttons. Click a node to select it and slide open the detail panel (360px) on the right, showing properties, connections, and external links. Click the background to deselect.

### Finding a specific service

Use the workload finder (search bar at the top of the canvas) to type a service name. The graph zooms to and highlights the matching node.

You can also use the URL parameter `?focus={nodeId}` to link directly to a focused node. Other pages (Foresight, Incidents) use this to link into the topology.

## Focusing on a service's neighborhood

Right-click a node and select **Focus**. The graph filters to show only nodes within N hops of the selected service. A depth slider lets you expand or contract the neighborhood.

To return to the full view, click the reset button that appears, or right-click and select **Reset view**.

## Tracing dependencies

Hover over a node to highlight it and all its connected edges. Everything else dims, so you can see the dependency paths clearly. Animated flow dots travel along edges to show call direction.

Click an edge to select it and see the relationship type (calls, depends-on, reads-from, etc.) in the detail panel.

For cross-container relationships (e.g., a service in one cluster calling a service in another), bundled lines appear between container borders. Hover a bundle to see the count and type breakdown.

## Viewing service details

Click a node to open the detail panel. For the full-page view, click **View full details** in the panel. The service detail page has four tabs:

The Overview tab shows properties, connection summary, linked documents, PagerDuty services, and Jira issues. Connections lists outbound calls in a table. History shows PR review history from Foresight and incidents for this service. External links to GitHub, cloud console, and shows runtime details (Kubernetes pods, GCP VMs).

## Asking questions about the topology

Right-click any node and select **Ask Cielara**. The AI assistant opens with a pre-built prompt that includes the node's name, kind, layer, repo, languages, cluster, namespace, and up to five relationships. You can ask follow-up questions in the same conversation.

You can also open the Ask Cielara panel from any page and type topology questions directly, such as "What services depend on the payments API?" or "Show me the blast radius if Redis goes down."

## Managing favorites

Right-click a node and select **Favorite**, or click the star on its card. Favorited nodes are saved per-user. Open the graph with `?favorites=1` to see only your starred nodes.

## Switching layouts

Within containers, nodes default to a grid arrangement. The toolbar lets you switch to layered, tree, force, radial, or stress layouts. These run in a web worker so the UI stays responsive on large graphs.

## Managing document mappings

<Info>
  Document mapping requires admin access and the auth layer feature flag. It appears as **WM Editing** in the sidebar.
</Info>

The World Model auto-links documents to workloads, but the mapping isn't always correct. To fix it:

1. Click **WM Editing** in the sidebar.
2. In the left panel, search for and select the workload you want to fix.
3. The center panel shows its currently linked docs. The right panel shows all available files from Agent Memory, filterable by source (Notion, GitHub, Slack, Confluence).
4. **To add a link**: select files in the right panel and drag them onto the center panel.
5. **To remove a link**: select the document in the center panel and delete it.
6. Changes persist immediately. Use the undo button to reverse recent additions.

Click the eye icon on any document to preview its content with line numbers before linking it.
