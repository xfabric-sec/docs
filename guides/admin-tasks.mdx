All admin tasks require the Admin role. Admin-only pages appear in the **Configuration** group in the sidebar.

## Adding a user

1. Go to **Users & Access** in the sidebar.
2. Click **Create**.
3. Fill in the form:
   - **Email Address**: the user's email.
   - **User Role**: click one of the role chips:
     - **Admin**: full access to all features including configuration pages.
     - **User**: access to Analytics, World Model, Ask Cielara, Deep Inquiry, Simulations, Memory Explorer, and Connections (viewing only).
4. Click **Add User**.

The user receives an invitation. They complete registration and set their password.

### Editing a user

1. Click a user in the list to open their profile.
2. Change their role or account status:
   - **Active**: the user can sign in.
   - **Inactive**: the account is preserved but sign-in is blocked.
3. Click **Update User**.

<Warning>
  If the user you're editing is the only admin, the Admin role is locked. Add another admin before changing their role.
</Warning>

## Configuring an LLM provider

Cielara needs at least one LLM provider for AI features to work. Go to **Models** in the sidebar.

### Step 1: Select a provider

Choose from the **Primary LLM Provider** dropdown:

| Provider | Description |
|---|---|
| OpenAI | GPT models via the OpenAI API |
| Microsoft Foundry | GPT or Claude models via Azure |

A summary card shows which model Cielara will use for each job and what credentials you need to supply.

Click **Next: Configure & Test**.

### Step 2: Configure and test

The form depends on which provider you selected:

**OpenAI**:
- **API Key**: paste your key (from platform.openai.com > API keys).
- **Base URL** (optional): only change if using a proxy. Defaults to `https://api.openai.com/v1`.

**Microsoft Foundry (Azure OpenAI / GPT)**:
- **Endpoint**: your Azure OpenAI endpoint (e.g., `https://my-aoai-resource.openai.azure.com/`). Must be HTTPS.
- **API Key**: from Azure Portal > AI Foundry > Keys and Endpoint.
- For each model category (Reasoning, Coding, Mini, Embedding): a **Deployment name** field. Enter the name from Azure Portal > AI Foundry > Deployments.

**Microsoft Foundry (Azure Anthropic / Claude)**:
- **Foundry Resource Name**: your AI Foundry resource name (e.g., `my-foundry-resource`).
- **API Key**: from Azure Portal > AI Foundry > Keys and Endpoint.
- For each model category: a **Deployment name** field.

Cielara tests each model as you configure it. A row that fails tells you why, so you can tell a wrong API key from a missing deployment.

Click **Save & Continue** when all models verify.

### Step 3: Set a budget

If your deployment has budgets enabled, set spending limits before activating:

- **Monthly Limit (USD)**: minimum $1,000.
- **Duration**: Daily, Weekly, Monthly 30d, or Monthly calendar.

When you have more than one provider configured, you can set a separate budget for each.

Review the summary and click **Activate**. Otherwise the provider activates as soon as you save.

## Setting up SSO

Cielara supports single sign-on through Google Workspace or any SAML 2.0 identity provider. See [Authentication](/authentication) for the full setup steps, including the values you need to register with your provider.
