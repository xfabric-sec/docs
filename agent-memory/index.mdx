Agent Memory is a document-to-knowledge pipeline for AI agents. It ingests documents in multiple formats, extracts atomic memories using LLMs, and retrieves them through an iterative, multi-step process with hybrid search.

## How it works

Agent Memory processes documents through a four-layer pipeline:

1. **Normalization**: adapters convert Markdown, PDF (via Docling or Marker), and DOCX files into a uniform format
2. **Segmentation**: hierarchy-aware chunking (default: 2000 chars, 200 overlap, 500 min)
3. **Memory extraction**: LLM extracts atomic facts, generates embeddings (text-embedding-3-small), deduplicates at 0.90 similarity threshold
4. **Retrieval**: policy-driven MDP with hybrid search (semantic + BM25 + cue anchors)

## Key features

- **Hybrid search**: combines vector similarity (ChromaDB/pgvector), keyword ranking (BM25), and cue-based anchoring
- **Policy-driven retrieval**: an MDP that iteratively expands, refines, decomposes, or terminates search (max 5 steps)
- **Question answering**: ask questions and get grounded answers with citations, evaluated by a judge model
- **Multiple collections**: organize memories by project, team, or domain with full storage isolation
- **Connectors**: pull documents from Notion, Google Drive, and Canva
- **Memory graph**: memories link via sibling, shared_anchor, same_document, and hierarchical edges
- **Prometheus metrics**: full observability on HTTP, LLM, retrieval, ingestion, and QA operations
