The World Model is a continuously updated graph of your services and how they connect. Click **World Model** in the sidebar to open it.

The page renders a full-screen interactive canvas built on Sigma.js. Services appear as card-shaped nodes (not circles) inside nested cluster and namespace containers, with animated flow dots traveling along edges to show call direction.

## What the graph shows

Nodes represent different entity types across your estate:

- Workloads (microservices, APIs, background workers)
- Data stores (databases, caches, queues)
- External services (third-party APIs, SaaS dependencies)
- Infrastructure (clusters, namespaces, deployments, pods, service accounts)
- Repositories linked to workloads
- PagerDuty services, Jira projects, and wiki documents

Edges show relationships: calls, depends-on, publishes-to, reads-from, deployed-in, owns.

Nodes are color-coded by ontology layer (Logic, Topology, Runtime, Intent, Policy, Persona, Auth). A legend in the corner explains the color mapping for layers, edges, and containers.

## Layout

The graph uses a grouped layout: workloads are nested inside cluster and namespace container boxes. Cross-container relationships show as bundled lines between container borders. Hover a bundle to see the count and type breakdown.

Within containers, you can switch card arrangement between grid (default), layered, tree, force, radial, and stress layouts. The non-grid options use ELK.js running in a web worker.

## Interacting with nodes

Click a node to select it and open the detail panel on the right (360px). The panel shows the node's properties, layer, kind, health, connections (inbound and outbound with relationship types), and links to external systems (GitHub, cloud console, PagerDuty).

Right-click a node to open a context menu with options: Focus (filter the graph to N-hop neighbors, with a depth slider), Hide, Expand/Collapse, Ask Cielara (opens the AI assistant with a prompt about this node), and Favorite.

Hover a node to highlight it and its connected edges, dimming everything else. Click the doc badge on a node (e.g., "3 docs") to see a popover listing linked wiki documents. Drag a node to reposition it within its container.

## Interacting with edges

Hover an edge to highlight it and both endpoints. Click an edge to select it and open an edge detail panel showing the relationship type, source, target, and properties.

## Service detail page

Click "View full details" in a node's detail panel to open a full-page view at `/production-world-model/service/{id}`. The detail page has four tabs. Overview shows properties, connection summary, linked documents, PagerDuty services, and Jira issues. Connections lists outbound calls in a table. History shows PR history from Foresight reviews and incidents associated with this service. External links to external systems and shows runtime details (Kubernetes pods, GCP VMs).

Node types with dedicated views include workloads, deployments, pods, service accounts, namespaces, documents, design docs, data stores, external services, repositories, PagerDuty services, and auth entities.

## Ask Cielara integration

Right-click any node and select "Ask Cielara" to open the AI assistant with a pre-built prompt that includes the node's name, kind, layer, repository, languages, cluster, namespace, and up to five relationships. The assistant answers in context.

Ask Cielara can also embed the World Model view inline in a chat conversation via an iframe (using `?embed=1`).

## URL parameters

- `?focus={nodeId}`: opens the graph focused on a specific node (used by cross-page links from Foresight and Incidents).
- `?favorites=1`: opens the graph filtered to your starred nodes only.

## Navigation

Zoom and pan with your mouse or trackpad. Zoom controls (in, out, fit-view) sit in the bottom-left corner. A minimap appears in the corner for orientation on large graphs.
