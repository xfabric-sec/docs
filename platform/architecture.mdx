The xFabric platform is a monorepo containing six services that work together behind a unified edge layer.

## Services

| Service | Port | Language | Description |
|---|---|---|---|
| **insights-backend** | 8080 | Go | Core API: JWT+RBAC auth, 30+ route groups, graph-based entity modeling (FalkorDB), cloud provider plugins (AWS/Azure/GCP/K8s) |
| **admin-backend** | 8100 | Go | Identity provider: login, SSO, signup, IAM CRUD, user management, email (SendGrid) |
| **agent-fabric** | 3001 | Python | Multi-agent system: code review, simulations, World Model, deep inquiry. Internal-only, no direct ingress |
| **rca-agent** | 3000 | Python | Root cause analysis agent |
| **agent-memory** | 8001 | Python | Policy-driven memory system: document ingestion, retrieval, question answering |
| **mcp-server** | 8888 | Python | Model Context Protocol server for AI tool access to platform capabilities |

## Backend architecture

The Go backend uses a plugin system for multi-cloud support:

- **Cloud provider plugins**: AWS, Azure, GCP, and Kubernetes, each implementing a common interface for resource discovery and scanning
- **Graph-based modeling**: FalkorDB for entity relationships, supporting 78+ entity types
- **Inventory system**: unified asset inventory across cloud providers

The frontend is a Next.js 13+ app using the App Router, Material-UI, TypeScript, and React Query.

## Edge routing

All external traffic enters through a single edge layer that routes to the appropriate backend service. Internal services (agent-fabric, rca-agent) are not exposed to the internet and communicate via internal service mesh.

```
Client → Edge/ALB → insights-backend (:8080)
                   → admin-backend (:8100)
                   → agent-memory (:8001, JWT via ALB prefix)
                   → mcp-server (:8888, static bearer token)

Internal only:
  agent-fabric (:3001) — proxy JWT from insights-backend
  rca-agent (:3000) — internal mesh
```

## Deployment

The platform runs on Google Kubernetes Engine (GKE) and is deployed as Docker containers with Helm charts. Local development uses Docker Compose with k3d.

| Environment | Stack | Notes |
|---|---|---|
| **Production** | GKE + Helm | Per-cloud assemblers for GKE/EKS/AKS differences |
| **Local dev** | Docker Compose + k3d | Mirrors production topology |
| **Production VM** | Docker Compose | For single-node deployments |

Database migrations use golang-migrate, auto-applied during Docker Compose startup. Migration files live in `admin-backend/cmd/install/migrations/` following the `{version}_{description}.up.sql` / `.down.sql` convention.
